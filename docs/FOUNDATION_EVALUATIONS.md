# Foundation evaluation harness (bundle schema 1.1)

This harness runs only the existing local synthetic foundation provider. Its tiny fixtures test plumbing and deterministic policy gates; their scores do not measure finance, editorial, retrieval, or real-model quality. No real judge or publication is implemented. Local synthetic release governance and explicit Phoenix/offline export are documented separately.

Run each split explicitly:

```sh
.venv/bin/python -m app.evals.run --agent foundation --dataset evals/foundation/1.0.0 --split dev --output data/evals
.venv/bin/python -m app.evals.run --agent foundation --dataset evals/foundation/1.0.0 --split holdout --output data/evals
.venv/bin/python -m app.evals.run --agent foundation --dataset evals/foundation/1.0.0 --split prod_regression --output data/evals
```

`--repeats` defaults to 1 and `--seed` to 0. The arithmetic fixture is deterministic and consumes no RNG; seed records the experiment identity. Every selected example runs on every repeat, including after earlier execution/evaluator failures. Each split run independently revalidates all three nonempty dataset split files and compares selected actual examples against that authoritative load. A single-split PASS is not a cross-split release approval.

The fixture stage checks actual source IDs, `AWAITING_APPROVAL`, pinned artifact version, and metadata before invoking the typed fake increment. Scenario names and expected labels cannot authorize acceptance. A correctly blocked invalid fixture passes its safety check. Contract, policy, evidence, state, metadata, and explicitly synthetic rubric checks are required. Missing/duplicate/unknown evaluator coverage or results, skipped required checks, absent denominators, empty datasets, and partial runs are incomplete. Judge/runner failures are errors, never zero-score substitutes. Any failed required check or critical false accept fails regardless of averages.

The rubric adapter pins judge identity/version/source, prompt identity/version, and calibration bytes. Its supplied calibration contains a typed example and typed positive/negative output anchors, both executed against the actual callable before each example score; it has no human editorial calibration. Changing the callable changes evaluator provenance. Function code (with recursively normalized code filenames), source, and supported immutable global dependencies, including global/builtin loads inside nested code, are pinned and rechecked before/after calibration and evaluation; closures, defaults, callable instances, mutable global dependencies and opaque state are rejected. It cannot evaluate a real agent. Custom local evaluator implementations must provide stable IDs, versions and fingerprints; class source is also pinned, and an uninspectable implementation fails closed. This is not an arbitrary remote judge/plugin runner.

Experiment bundles retain full per-example typed outputs, errors as safe codes, repeats, latency/retry observations, optional paired ordered `started_at`/`finished_at` from actual attempt records, trace IDs, usage availability, model parameters and evaluator versions. They bind code HEAD and tracked dirty diff plus new source-file hashes, dataset/version, schemas, prompt, config, evaluator and policy hashes. Scores and provenance are reproducible with stable source/configuration; UUIDs, timestamps and traces intentionally make real execution bundle hashes distinct. Unknown token counts/costs remain null; a partial measurement cannot imply zero cost. Aggregates include samples and denominators. They do not replace per-example records or per-repeat coverage.

CLI stdout contains only counts, hashes, status and the restricted bundle path. `repr` and summaries omit per-example contents. Bundle JSON is privileged local evidence, including for holdout. Files use mode 0600 and new output directories use mode 0700. Do not attach private bundle JSON to ordinary logs. The wrapper contains `bundle_hash` and the exact `bundle`; filename, content hash, internally derived status/aggregates, mandatory provenance/evaluator versions, and embedded config/model/parameter/output pins are checked when consumed. A FAILED output envelope is an execution error even if its redundant row error flag is missing. Persistence writes and fsyncs a private temporary file, then atomically publishes complete bytes using a no-clobber hard link; interruption can leave an unpublished temporary file after a process kill but cannot expose partial final bytes. Identical concurrent writers converge on the same complete artifact; different bytes at its hash path remain a conflict. Frozen models are revalidated rather than trusted as deeply immutable. A local operator can replace files: hashes provide integrity, not authenticated authorship.

Bundle 1.1 stores ordered evaluator identity, version, configuration fingerprint and implementation hash. The evaluator hash pins that configuration even when an evaluator returns zero rows. The summary reports the configured and observed evaluator IDs separately. The release gate checks the installed implementation and recomputes each required result.

Each example retains an ordered usage record per journaled attempt, including retries. The aggregate sums each measurement once and leaves a field null if a contributing attempt lacks that measurement. For critical rejection cases, the summary exposes the expected and observed outcome counts and the observed false accepts. The total false accepts is null when coverage is incomplete. Fresh runs produce 1.1 evidence. Archived 1.0 bundles lack these fields and require a fresh run for current comparisons and release checks. Archived files remain intact.

The offline export includes one `evaluator.run` child per evaluator invocation. Its parent is the evaluated attempt, including when the evaluator returns an error or raises. The foundation demo checks the exported parent and evaluator IDs for all 54 original checks. A release gate recomputation is separate from that experiment.

The local runtime directory contains SQLite execution journals, immutable typed artifacts and telemetry outbox. The existing `Telemetry.export_offline(path)` writes the fallback trace bundle; `test_evaluation_traces_have_working_offline_export` exercises this after a real experiment. CLI cleanup closes the business connection and calls `telemetry.shutdown(0)`, leaving pending traces local without network flush. No running Phoenix service is needed for offline evaluation or release review. The execution journal stores attempt details. Missing telemetry does not silently discard agent output.

Compare the candidate path printed by a run against a compatible bundle:

```sh
.venv/bin/python -m app.evals.compare --agent foundation --candidate data/evals/ACTUAL_HASH.json --baseline tests/fixtures/evals/synthetic-baseline-v1.1.json
```

`synthetic-baseline-v1.1.json` is a synthetic development fixture. Comparison requires matching dataset/version/schema/evaluator/policy pins, split, repeats, seed and exact example/repeat membership. Code, prompt and model can differ intentionally. Changed dataset or evaluator policy requires a reviewed common rerun outside this slice; there is no bypass flag. Comparison retains private failing example IDs through the Python report and only a failure count in routine output. Exit codes are 0 for complete pass/compatible pass, 1 for a complete failed candidate, and 2 for error, incompleteness, corrupt bundle or incompatibility. Use `--baseline approved --registry data/state.db` to resolve a human-approved registry baseline. Initial synthetic success is never automatic approval; see [RELEASE_GOVERNANCE.md](RELEASE_GOVERNANCE.md) for release eligibility, offline review, the default-deny authentication seam, and limitations.
